# Contributing to Quik Web

Thanks for looking. This is a small project and every bug report, idea and pull request helps.

## How changes get in

1. Fork the repository and create a branch from `main` (for example `feature/wipe-transition`).
2. Make the change. Keep one topic per pull request.
3. Test it in a desktop browser and, if it touches playback, export or layout, on a real phone (see below).
4. Open a pull request against `main`. Fill in the template.
5. The maintainer (@ittaymiz) reviews and merges. Nobody pushes to `main` directly, including the maintainer.
   `main` deploys straight to <https://ittaymiz.github.io/quik-web/>, so whatever is merged is live within a minute.

No build step, no dependencies to install. Open `index.html` or run `python3 -m http.server 8000`.

## Where things live

| File | What it does |
| --- | --- |
| `index.html` | The whole UI: tabs, panels, buttons. |
| `styles.css` | Styles, including the phone layout. |
| `js/app.js` | Timeline model, canvas renderer, playback, audio graph, Auto Create planner, export. |
| `js/presets.js` | Looks (`FILTERS`), themes (`THEMES`), pace settings. Easiest place to add something. |
| `js/beats.js` | Beat detection for music sync. |
| `js/db.js` | IndexedDB persistence (database `quikweb`). |
| `js/vendor/` | Third-party libraries: face-api.js, mp4-muxer, mediabunny. Keep their licence files. |
| `music/` | Built-in tracks and `library.json`. Tracks are generated by `tools/make_music.py`. |
| `sw.js` | Service worker. Bump the cache name when you change precached files. |

## Testing on a phone

Safari on iOS needs HTTPS. The simplest route: push your branch to your fork, enable GitHub Pages
(**Settings → Pages → Source: GitHub Actions**) and the included workflow deploys it. Then open
`https://<you>.github.io/quik-web/` on the phone and add it to the home screen.

For a quick local check, serve the folder and open it from a phone on the same Wi-Fi via the
computer's IP. Chrome on Android works over plain HTTP; Safari needs HTTPS for the service worker and
for `navigator.share`, but the editor itself still runs.

## Ground rules

- Keep it dependency-free and build-free. If a library is unavoidable, vendor it into `js/vendor/` with its licence.
- Nothing may phone home. No analytics, no remote fonts, no CDN scripts. Media must never leave the device.
- Music you add must be your own work or CC0, and say so in `music/library.json`.
- Match the existing style: plain ES modules, no framework, two-space indent.
- If you change export, test an iPhone export and check the audio plays back.

## Reporting bugs

Open an issue with the device, OS version, browser, what you did, what happened, and the diagnostics
report if export was involved (**Export → technical report**). A short screen recording helps a lot.
